# Session 2026-10-08 · b9482f08

Built with Claude Code on Claude Opus 5.5, with sub-agents for the larger tasks. This record covers the whole session, from the first rules to the first beta candidate, including Avala used for real with Claude Code.

## What was done

- Named the project, created the repository and chose the MIT license.
- Defined the rules and wrote the architecture tests before any feature: modular monolith, view-model-first MVVM, sealed classes, no comments, a 600-line limit, no blocking calls, at most four constructor dependencies, no nullable signatures, C# only scripting.
- Studied T3 Code's architecture and history to avoid its failure modes.
- Phase 1, foundations: the SDK, the result pattern, the event bus, the DDD and boundary rules with compliant and violating fixtures.
- Phase 2, the Jobs domain and its lifecycle.
- Phase 3, the Agents core: agnostic events with telemetry and streaming canvases, turn integrity and a conformance kit.
- Phase 4, Workspaces: git worktrees with checkpoints over an asynchronous process runner.
- Phase 5, the job flow end to end: launcher, turn checks, completion gates, recovery after a restart, persistence with EF Core and SQLite, Option instead of nulls.
- A simulated Claude Code provider built only on the public contracts, and simulation tests of the real application composed from its plugin folder. They caught two bugs that every other test had missed: two modules were never published as plugins, and shared contracts were loaded once per plugin.
- CI on Linux and Windows with coverage and lines of code, and this session record.
- Screaming architecture: module folders and namespaces named after behavior, with every namespace assigned to a layer in one map that the architecture tests enforce.
- Phase 7, Observability: tokens, cost, limits and turns aggregated by provider, session and job, plus metrics through `System.Diagnostics.Metrics`, checked with a simulated job.
- Phase 8, Canvas: streamed canvases accumulated per item and published as throttled snapshots, checked with the simulator's canvas scenario.
- The trust layer: verification of declared checks with evidence, permission policies with an audit, holding a job from outside with a typed reason, supervision of stalled or lost sessions, budget caps, and every repository rule read from the job's base commit.
- Concurrency only through the event bus or channels: one mailbox per handler, one queue per job, and no locks or semaphores in production code, enforced by an architecture rule.
- The provider contract grown with resume tokens, injected harness tools (the canvas tool first) and accounts, each with its simulator implementation and conformance check.
- Generic human-input forms and autonomy levels, so a repository can let its jobs run unattended while every automatic answer is audited.
- Session recording and replay: any session can be recorded in a versioned format and replayed by the simulator as a regression test.
- Connections, resources, review and approval, the autopilot and delegation, all proven on the simulator.
- The view models of every screen, then the real Avalonia views built to the approved Claude Design brief, with regions, design-time view models, scripted acceptance tests per component and page, and view and XAML architecture rules.
- Determinism: no waits on time anywhere, enforced by the compiler and an architecture rule; host tests on a controllable clock waiting on events.
- Quality metrics with open-source analyzers, a public technical-debt grade and badges published by the CI.
- The real Claude Code provider: the stream-json CLI behind an in-process MCP server, every acting tool asked through Avala's policy, the user's own configuration loaded under Avala's permissions, and recordings of real sessions replayed by the simulator.
- Connections chosen by capacity across accounts and harnesses, with a default connection the user picks.
- Capabilities as typed components that providers attach and connections refine.
- Screen honesty: everything a screen shows survives a restart through EF Core migrations, no label claims more than the data says, and conversations, checks and delegated children resume across restarts.
- Steering a running agent, usage windows, settings edited in the app, a light theme, reduced motion, Markdown replies and Mermaid as an optional renderer.
- Beta and release preparation: one instance per data folder, a first-run guide, a diagnostics log, packages for Windows, Linux and macOS, a release workflow that only drafts, and an update check.
- CI on Linux, Windows and macOS, with hang dumps instead of hung jobs.
- Two technical-debt passes without changing the formula, one of them unifying the shell command reader that permissions and the interface share.
- Avala used for real: two runs where Claude Code built small apps through the composed application for $1.60 in total. They found what no simulation had: command rules that approved chained commands, a restart during checks that relaunched the agent, a conversation lost after a restart, and an inspector empty until its data was restored. All were fixed and confirmed by the second run.
