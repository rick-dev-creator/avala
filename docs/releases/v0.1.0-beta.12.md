**What exists, made reliable.**

The twelfth beta of Avala, for Windows and Linux. It is a **prerelease**: expect rough edges, and please report them. Installed with the Windows installer, the portable zip or the AppImage, an earlier beta offers this update in place.

## What changed since 0.1.0-beta.11

No new features: this beta fixes what a trial of 0.1.0-beta.11 found, and what adversarial review found while fixing it.

**No agent outlives Avala.** Quitting Avala now waits for every agent session to stop and its processes to close, at most 20 seconds; before, every Claude Code process outlived Avala. An agent left idle, a job waiting for your review or your answer, a chat, or an archived conversation, ends once its prompt cache has expired, after an hour, or at once when you archive it, and your next message resumes the conversation as after a restart. A job waiting on your answer to a permission or a form keeps its agent. Processes an earlier run left behind are closed when Avala starts, and a job that ends stops every delegated child it left behind.

**An approved job takes a message.** Writing to a job after Review and Approve reopens it in the same conversation and brings it back for review.

**The plan is followed to the end.** With docs on, a job's agent is asked for its task list before it starts and asked to keep it up to date with every message that starts a round, retries after failing checks included, so the feature's versions follow the plan to the end, across a restart too.

**The C4 player zooms and pans.** In the Docs pane, on a feature's page and on the docs site: the wheel at the pointer (with Ctrl or ⌘ where the page scrolls), pinch, drag, zoom buttons, actual size and fit to view. Labels sit on plates, relations go around elements, and the diagram is centred. A diagram that declares one element twice draws it once, and a version that cannot be played is named instead of freezing the pane.

**Menus and the usage popup read well.** Menus and tooltips share the app's look, open with nothing highlighted and set deleting apart in red. The usage popup opens under its chip with each window's use and reset. The composer and the job header fit narrow windows without hiding an action, and the Usage page reflows.

**A job without checks shows what the agent ran** ([#127](https://github.com/rick-dev-creator/avala/issues/127)). The review and Evidence list the agent's own build, test and lint commands after its last edit, as reported by the agent, never as verification, and Evidence offers **Declare checks**.

**The agent's pull request is followed** ([#128](https://github.com/rick-dev-creator/avala/issues/128)), even from a branch its worktree never checked out, when the agent pushed it from this clone; a colleague's pull request it merely names is not.

**Read-only commands are stricter.** A command allowed without asking because it only reads now accepts only the options known to read, written in full. Some commands that could write a file or run a program passed as read-only before; they ask now. A line with an unquoted glob, such as `wc -l src/*.cs`, also asks.

Everything else is as described in the [0.1.0-beta.11 notes](https://github.com/rick-dev-creator/avala/releases/tag/v0.1.0-beta.11).

## Supported harness

- **Claude Code.** Avala runs the `claude` CLI in its streaming JSON mode, so Claude Code must be installed, with `claude` on the `PATH`, and signed in. Avala finds each login on its own: the default `~/.claude` folder, other `~/.claude-*` folders, the folder in `CLAUDE_CONFIG_DIR`, or an API key or token in the environment, and offers a connection for each.

Each package is self-contained, and every installer and archive has a `.sha256` checksum next to it. The builds are still unsigned: Windows SmartScreen warns about an unknown publisher, and Linux packages are checked against their `.sha256`.

## Check a package before trusting it

`./Avala --version` prints `Avala 0.1.0-beta.12 (<commit>)`, and `./Avala --smoke` starts the real application headless in a temporary data folder and prints `Avala <version> composed <n> pages and showed its main window.` On Windows, pipe them to `Out-Host` in PowerShell.

## Privacy

Unchanged from 0.1.0-beta.1: anonymous usage statistics to [Aptabase](https://aptabase.com), on by default, an `installed` event once and an `active` event at most once per local day, and nothing about your repositories, jobs, prompts, paths, harnesses, connections, accounts, costs or features. Turn it off on the first-run notice, in Settings, About, or with `DO_NOT_TRACK=1` or `AVALA_TELEMETRY=0`. Attachments and drafts stay on your machine; attachments go only to the harness of the job they were sent with.

## Known limitations

- This is a beta prerelease, told about later prereleases as well as stable releases.
- Windows and Linux only for now; macOS packages come later.
- Packages are unsigned.
- Claude Code is the only supported harness.
- No Flatpak on Flathub yet; the Flatpak can be built from the tar.gz.
- The Archived page has no search yet, and nothing is archived automatically.
- A peek shows text files only; images and pages open in their own preview.
- Continue on your phone needs a harness that offers it: today Claude Code signed in with claude.ai. Turned on after an agent ended for being idle, it reaches the agent once the job runs again.
- The welcome screen's composer does not take attachments yet; attach them once the job has started.
- Whether Claude Code's own sub-agents compact at their connection's window has not been confirmed yet.
- Feature documentation writes a version for a new plan or an attempt that changes it; code the diff touches outside the plan does not write one yet.
- Without declared checks, what counts as the agent's verification and as an edit is read from its commands, so an unusual tool can be misread. A pull request pushed by URL instead of a remote's name is not adopted.
- A docs site job approved under `keep` leaves the site on its branch; merge it yourself.
