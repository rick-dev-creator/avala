**Every job documents its feature as it is built.**

The tenth beta of Avala, for Windows and Linux. It is a **prerelease**: expect rough edges, and please report them. Installed with the Windows installer, the portable zip or the AppImage, an earlier beta offers this update in place.

## What changed since 0.1.0-beta.9

**Feature documentation** ([#112](https://github.com/rick-dev-creator/avala/issues/112)). Turn it on per repository in Settings, Repositories, or with `{ "docs": { "enabled": true } }` in `.avala/jobs.json`. When a job's harness proposes a plan, a small documentation companion on the repository's `research` role writes the feature's version as Markdown with a Mermaid C4 diagram, committed in the job's branch under `docs/features/<feature>/` with the plan, an index and a `toc.yml`; a new plan writes a deviation, and Avala writes **As built** itself when the job is ready for review, with its checks and changed files. New job shows the feature it suggests as a chip under the instruction, to keep, change or turn off.

**Change requests and the connected history** ([#113](https://github.com/rick-dev-creator/avala/issues/113)). Every steer, send back and message that starts an attempt is recorded, explained by the next version and listed in `changes.md`. The job's Docs pane shows its plans in order with the requests between them, and for each one what happened, why it deviated and what changed.

**The C4 player** ([#114](https://github.com/rick-dev-creator/avala/issues/114)). Avala draws each version's C4 in its own style and plays it from the one before: new elements appear, changed ones are highlighted, removed ones fade, and a flow plays hop by hop. The document follows each step, and choosing a section moves the diagram to it.

**Docs in Avala** ([#115](https://github.com/rick-dev-creator/avala/issues/115)). A project's sidebar lists its documented features under **Docs**, each on its own page with its versions and the player. Inside a job, the **Docs** glyph opens a pane with its feature, player and history, and the conversation shows a quiet line for each version and change request.

**The docs site** ([#116](https://github.com/rick-dev-creator/avala/issues/116)). **Create site** lays the docs out with DocFX the way Microsoft Learn structures documentation, and starts a job that fills the overview, quickstart, architecture and configuration. Significant decisions get architecture decision records linked with their versions, and each As built adds its entry to `whats-new.md`. Each C4 diagram on the site is Avala's player, `<avala-c4>`, a web component that plays the diagram level by level and a flow hop by hop. A job's Docs pane opens the site in the Preview pane, with DocFX installed (`dotnet tool install -g docfx`).

**Fixed.** A repository whose `.avala/jobs.json` declared delegation `roles` had the whole file rejected, so its jobs could not start.

Everything else is as described in the [0.1.0-beta.9 notes](https://github.com/rick-dev-creator/avala/releases/tag/v0.1.0-beta.9).

## Supported harness

- **Claude Code.** Avala runs the `claude` CLI in its streaming JSON mode, so Claude Code must be installed, with `claude` on the `PATH`, and signed in. Avala finds each login on its own: the default `~/.claude` folder, other `~/.claude-*` folders, the folder in `CLAUDE_CONFIG_DIR`, or an API key or token in the environment, and offers a connection for each.

| Arch Linux | `avala-bin-0.1.0-beta.10.PKGBUILD` | the recipe of the AUR package `avala-bin`, built from the tar.gz |

Each package is self-contained, and every installer and archive has a `.sha256` checksum next to it. The builds are still unsigned: Windows SmartScreen warns about an unknown publisher, and Linux packages are checked against their `.sha256`.

## Check a package before trusting it

`./Avala --version` prints `Avala 0.1.0-beta.10 (<commit>)`, and `./Avala --smoke` starts the real application headless in a temporary data folder and prints `Avala <version> composed <n> pages and showed its main window.` On Windows, pipe them to `Out-Host` in PowerShell.

## Privacy

Unchanged from 0.1.0-beta.1: anonymous usage statistics to [Aptabase](https://aptabase.com), on by default, an `installed` event once and an `active` event at most once per local day, and nothing about your repositories, jobs, prompts, paths, harnesses, connections, accounts, costs or features. Turn it off on the first-run notice, in Settings, About, or with `DO_NOT_TRACK=1` or `AVALA_TELEMETRY=0`. Attachments and drafts stay on your machine; attachments go only to the harness of the job they were sent with.

## Known limitations

- This is a beta prerelease, told about later prereleases as well as stable releases.
- Windows and Linux only for now; macOS packages come later.
- Packages are unsigned.
- Claude Code is the only supported harness.
- No Flatpak on Flathub yet; the Flatpak can be built from the tar.gz.
- The Archived page has no search yet, and nothing is archived automatically.
- A peek shows text files only; images and pages open in their own preview.
- Continue on your phone needs a harness that offers it: today Claude Code signed in with claude.ai. A sub-agent shows what it does and its state, not its type.
- The welcome screen's composer does not take attachments yet; attach them once the job has started.
- Whether Claude Code's own sub-agents compact at their connection's window has not been confirmed yet.
- Feature documentation writes a version for a new plan or an attempt that changes it; code the diff touches outside the plan does not write one yet.
