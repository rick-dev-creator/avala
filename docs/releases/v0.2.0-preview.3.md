**A Fleet page that shows the trend, and worktrees freed even when the agent switched branch.**

The third preview of Avala 0.2, for Windows and Linux. It is a **prerelease**: expect rough edges, and please report them. Installed with the Windows installer, the portable zip or the AppImage, 0.2.0-preview.2 and earlier offer this update in place.

## What changed since 0.2.0-preview.2

### The Fleet page shows the trend

The **Fleet** page now compares every range with the range of the same length right before it: the previous 7 days, the previous month, and so on.

- **Six tiles.** Spend, tokens, jobs, spend per job, cache hit and computers, each saying how it changed since the previous range. Spend and tokens draw a small chart of their days, weeks or months.
- **The chart.** By tokens, every column is split into input, output, reasoning, cache write and cache read. A line on every column marks what the same period of the previous range had, and its tooltip says how much.
- **The lists.** Every repository, computer and model says its part of the total and how it changed, or that it is new.
- **Show names.** While personal details are hidden, **Show names** reveals repository and computer names on the Fleet page alone, and leaving the page hides them again.
- **Any width.** The tiles, lists, chart and range options rearrange themselves in a narrow window.

The figures come from the server's existing route, so a fleet server on 0.2.0-preview.2 works unchanged.

### Worktrees freed even when the agent switched branch

An agent that checked out a branch of its own in its worktree, such as `fix/something`, left that worktree impossible to free: Avala tried again every ten minutes, the Worktrees page said it was due at the next sample, and **Free space now** wrongly blamed jobs that were working.

- **Freed when it is clean.** Such a worktree is now freed when nothing is left uncommitted. The agent's branch stays in your repository, and the job's own work is kept under `refs/avala/shelved/<id>` as before.
- **Kept, and said why.** A worktree with uncommitted changes on another branch, or with no branch at all, is still kept, and the Worktrees page now shows it as kept because "its checkout left its branch". **Free space now** counts the worktrees it kept for that reason.

Everything else is as described in the [0.2.0-preview.2 notes](https://github.com/rick-dev-creator/avala/releases/tag/v0.2.0-preview.2).

## Supported harness

- **Claude Code.** Avala runs the `claude` CLI in its streaming JSON mode, so Claude Code must be installed, with `claude` on the `PATH`, and signed in. Avala finds each login on its own: the default `~/.claude` folder, other `~/.claude-*` folders, the folder in `CLAUDE_CONFIG_DIR`, or an API key or token in the environment, and offers a connection for each.

## Check a package before trusting it

`./Avala --version` prints `Avala 0.2.0-preview.3 (<commit>)`, and `./Avala --smoke` starts the real application headless in a temporary data folder and prints `Avala <version> composed <n> pages and showed its main window.` On Windows, pipe them to `Out-Host` in PowerShell.

## Privacy

Unchanged from 0.2.0-preview.2. Anonymous usage statistics go to [Aptabase](https://aptabase.com), on by default: an `installed` event once and an `active` event at most once per local day, with nothing about your repositories, jobs, prompts, paths, harnesses, connections, accounts, costs or features. Turn them off on the first-run notice, in Settings, About, or with `DO_NOT_TRACK=1` or `AVALA_TELEMETRY=0`. A fleet server, only once you connect one in Settings, Fleet, receives what each job does, and nothing else.

## Known limitations

- This is a preview prerelease, told about later prereleases as well as stable releases.
- Windows and Linux only for now; macOS packages come later.
- Packages are unsigned.
- Claude Code is the only supported harness.
- **The fleet server:**
  - registered computers cannot be listed yet;
  - there is no web interface: the Fleet page in Avala is how you read the fleet;
  - only one server may run against a database.
