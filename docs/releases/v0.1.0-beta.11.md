**One honest ending for every job.**

The eleventh beta of Avala, for Windows and Linux. It is a **prerelease**: expect rough edges, and please report them. Installed with the Windows installer, the portable zip or the AppImage, an earlier beta offers this update in place.

## What changed since 0.1.0-beta.10

From using 0.1.0-beta.10 on Avala's own repository: the docs switch looked as if it turned itself off, the agent's pull request was not followed, a denial read as the pull request refused, approving said the job ended, the docs site never reached the folder, and nothing told what a repository needs before Avala works well.

**The docs switch tells the truth.** Settings shows what your working copy's `.avala/jobs.json` says. While that differs from the committed file, an amber dot says new jobs do not follow it yet, with **Commit .avala/jobs.json**, which commits that file alone on the checked-out branch and leaves anything else you staged as it was.

**What a repository needs is told when it matters.** A repository's first job opens with a card listing what it still needs, each with one action: connect the forge that hosts `origin` with the login Avala found ("Connect github.com as octocat through gh"), choose among several, or sign in and Check again; commit `.avala/jobs.json`; declare checks. A fixed item turns into a check mark in place, and Avala never connects a forge without you. The welcome tour's accounts say what they are for.

**The review names its action.** Instead of Approve, the review reads "Keep branch avala/<id>", "Merge into main", or "Open pull request on <connection>", the first action when a forge connection hosts `origin`, even without a `pullRequest` section, in which case the pull request is only watched. Approving says what happened: "Branch avala/<id> kept. Merge it when you are ready." or "Merged into main as 3f9a1c2." When `origin` is on a forge you have not connected, the review says so with **Open Settings**. A finished job's composer reads "This job is done", never "ended".

**Delivered jobs stay in sight.** A job whose pull request is open stays among its project's open jobs as "delivered · #123 · checks 2 of 3" until the pull request is merged or closed, then folds under done as "merged · #123" or "closed · #123". A pull request whose checks pass stays watched: "Checks passed · waiting for it to be merged".

**The agent's own pull request.** A pull request the agent opens from a branch it switched to in its worktree is adopted and watched like one on the job's branch. Without a usable connection, a pull request the agent reports is named once above its conversation: "Pull request #123 was opened by the agent. Connect github.com in Settings to follow its checks."

**A denial explains itself.** A write the policy denies outside the job's worktree reads "/tmp/pr-body.md is outside the job's worktree, and writing there needs you."

**The docs site is a job.** Create site no longer writes into your working copy. It starts a job whose worktree Avala lays out before its first turn, and the site is delivered like any job, so it reaches your docs folder once you merge it. Settings shows "Being prepared by its job" with **Open its job** until then, and offers Create site again if the job is discarded.

Everything else is as described in the [0.1.0-beta.10 notes](https://github.com/rick-dev-creator/avala/releases/tag/v0.1.0-beta.10).

## Supported harness

- **Claude Code.** Avala runs the `claude` CLI in its streaming JSON mode, so Claude Code must be installed, with `claude` on the `PATH`, and signed in. Avala finds each login on its own: the default `~/.claude` folder, other `~/.claude-*` folders, the folder in `CLAUDE_CONFIG_DIR`, or an API key or token in the environment, and offers a connection for each.

Each package is self-contained, and every installer and archive has a `.sha256` checksum next to it. The builds are still unsigned: Windows SmartScreen warns about an unknown publisher, and Linux packages are checked against their `.sha256`.

## Check a package before trusting it

`./Avala --version` prints `Avala 0.1.0-beta.11 (<commit>)`, and `./Avala --smoke` starts the real application headless in a temporary data folder and prints `Avala <version> composed <n> pages and showed its main window.` On Windows, pipe them to `Out-Host` in PowerShell.

## Privacy

Unchanged from 0.1.0-beta.1: anonymous usage statistics to [Aptabase](https://aptabase.com), on by default, an `installed` event once and an `active` event at most once per local day, and nothing about your repositories, jobs, prompts, paths, harnesses, connections, accounts, costs or features. Turn it off on the first-run notice, in Settings, About, or with `DO_NOT_TRACK=1` or `AVALA_TELEMETRY=0`. Attachments and drafts stay on your machine; attachments go only to the harness of the job they were sent with.

## Known limitations

- This is a beta prerelease, told about later prereleases as well as stable releases.
- Windows and Linux only for now; macOS packages come later.
- Packages are unsigned.
- Claude Code is the only supported harness.
- No Flatpak on Flathub yet; the Flatpak can be built from the tar.gz.
- The Archived page has no search yet, and nothing is archived automatically.
- A peek shows text files only; images and pages open in their own preview.
- Continue on your phone needs a harness that offers it: today Claude Code signed in with claude.ai. A sub-agent shows what it does and its state, not its type.
- The welcome screen's composer does not take attachments yet; attach them once the job has started.
- Whether Claude Code's own sub-agents compact at their connection's window has not been confirmed yet.
- Feature documentation writes a version for a new plan or an attempt that changes it; code the diff touches outside the plan does not write one yet.
- A pull request opened from another clone is not adopted, and a delivered job needs a forge connection to learn its pull request's fate.
- A docs site job approved under `keep` leaves the site on its branch; merge it yourself.
