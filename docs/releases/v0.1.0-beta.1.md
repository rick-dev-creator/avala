**Agents you can trust without watching.**

This is Avala's first public build, for Windows and Linux. It is a **prerelease**: expect rough edges, and please report them.

Avala is an open-source desktop harness for coding agents, written in C# on .NET 10 with Avalonia. It runs each agent in its own git worktree and lets it work unattended, while every decision is governed by your rules, every result is backed by evidence, and every cost is accounted for.

## What is in this beta

**Jobs in their own worktrees.** Each job runs in its own git worktree. Stalled or lost sessions are caught and held instead of hanging, and leftover processes, ports and worktrees are reclaimed. Jobs and their records survive a restart.

**Policies, not prompts.** Every permission request, question and plan approval is answered in place or by rules the agent cannot edit: built-in guards and defaults around the rules your repository commits, at the autonomy you allow, Supervised or Autonomous. Every decision is audited with the reason it was made.

**Evidence, not the agent's word.** A job is done only when the checks your repository declares pass in its worktree. The review shows that verdict first, then the diff, before the work is merged or kept.

**Budgets and usage limits.** Caps on cost, tokens, memory and provider limits per job and per connection, and a daily spending ceiling for the machine, hold a job before it overspends. A job that nears or runs out of an account's usage window waits for the reset and resumes in its conversation, or is handed off to another connection with room left, with a brief built from Avala's own records, as the repository or machine allows. Costs on a subscription login are shown as API-equivalent amounts, labelled "at API prices".

**Any agent, any account.** Several connections and accounts per harness, each with its own usage, cost and limits.

**Delegation.** An orchestrating agent can hand work to sub-agents that ask their parent first and run as child jobs, governed and verified like any other; a child's budget is carved out of its parent's.

**Loops, autopilot and triggers.** Autopilot works through a backlog unattended in loops with their own iteration and failure limits, and approves a job automatically only on clean evidence. Triggers start work as ordinary jobs on a schedule, on a signed webhook received on a loopback port only, or on a forge event from GitHub, Gitea or Forgejo: an issue labeled, a command in a comment, failing checks on a branch or a review requested. Forge events are polled, so a laptop needs no public endpoint; Avala never opens a public port.

**Pull requests and CI.** Avala opens a pull request for an approved job on GitHub, Gitea or Forgejo, watches its checks, reviews and conflicts, and wakes the agent when they fail, under the repository's policy.

**Best of N.** One request runs as several candidate jobs, each in its own worktree with its own checks and an even share of the budget. The best is kept by its evidence: a passing verification first, then the fewest exceptions and attempts, the smallest diff and the lowest cost. The others are discarded once you approve it.

**Phone notifications.** When a job needs you while you are away from the window, Avala notifies you through [ntfy](https://ntfy.sh) or a signed webhook of your own: a decision left to you, a held job, a budget or limit hold, a failed job, an ended loop, and optionally a job ready for review. Messages are minimal by default and are not sent if you answer in the app first.

**Canvas.** Agents can draw canvases as Markdown, sanitized SVG and Mermaid.

**The simulator.** A simulated harness plays scripted sessions through the same contracts as a real one, so Avala can be developed and tested without an agent account or tokens. The packages of 0.1.0-beta.1 include it, with the simulated forge and the session recorder, and offer a simulator connection only when Avala starts in developer mode, with the environment variable `AVALA_DEVELOPER=1`. It is a development tool, not a supported harness: the next build, 0.1.0-beta.2, leaves it out of every package.

Also: a light and a dark theme, and updates. Avala tells you when a newer version is out; installed with the Windows installer or as an AppImage, it downloads it when you click and installs it when you choose Restart to update, never on its own.

## Supported harnesses

- **Claude Code**, the only harness Avala officially supports. Avala runs the `claude` CLI in its streaming JSON mode, so Claude Code must be installed, with `claude` on the `PATH`, and signed in. Avala finds each login on its own: the default `~/.claude` folder, other `~/.claude-*` folders, the folder in `CLAUDE_CONFIG_DIR`, or an API key or token in the environment, and offers a connection for each.
The simulator in these packages is for developing and testing Avala only, and is not supported; it is gone from 0.1.0-beta.2 on. More harnesses plug in behind the same contract later.

| Windows x64 | `avala-0.1.0-beta.1-win-x64-portable.zip` | the same, unzipped anywhere, updating itself |

| Linux x64 | `avala-0.1.0-beta.1-linux-x64.tar.gz` | `avala-0.1.0-beta.1/` with `Avala`, `avala.png` and `avala.desktop`, for package managers and by hand |
| Arch Linux | `avala-bin-0.1.0-beta.1.PKGBUILD` | the recipe of the AUR package `avala-bin`, built from the tar.gz |

Each package is self-contained: nothing has to be installed first, and .NET is included. Every installer and archive has a `.sha256` checksum next to it, and the tar.gz, the folder inside the Windows installer and the AppImage were smoke-run in CI. The `.nupkg` and `releases.*.json` files are the update feed Avala reads; you never need them.

macOS packages come later. On a Mac, Avala builds and runs from source today.

## The builds are unsigned

- **Windows:** SmartScreen warns about an unknown publisher.
- **Linux:** packages are not signed; check them against the `.sha256` in the release.

## Check a package before trusting it

On Linux, from the extracted folder, or with the AppImage in place of `./Avala`:

```
./Avala --version
./Avala --smoke
```

On Windows, from the `current` folder of the unzipped portable package, or of `%LocalAppData%\Avala.Desktop` after installing; Avala is a windowed application, so in PowerShell pipe its output to see it:

```
.\Avala.exe --version | Out-Host
.\Avala.exe --smoke | Out-Host
```

`--version` prints `Avala 0.1.0-beta.1 (<commit>)`. `--smoke` starts the real application headless, with no display needed, in a temporary data folder: it loads every plugin, runs the startup tasks and migrations, shows the main window, prints `Avala <version> composed <n> pages and showed its main window.` and exits 0, or 2 if no plugin was found and 1 on a failure. Neither checks for updates or sends usage statistics.

## Privacy

This release sends anonymous usage statistics to [Aptabase](https://aptabase.com) so we can count installs and daily active installs. It is **on by default**. Nothing else leaves your computer on Avala's behalf.

- **What is sent:** an `installed` event once ever and an `active` event at most once per local day, each with Avala's version, your operating system's name, version and architecture, and a random install ID made on first run, never derived from your hardware, user name or paths.
- **What is never sent:** repositories, jobs, prompts, paths, harnesses, connections, accounts, costs, the features you use or your locale.
- **Turning it off:** choose Turn off on the notice shown on first run, or clear Send usage statistics in Settings, About; or set `DO_NOT_TRACK=1` or `AVALA_TELEMETRY=0` in Avala's environment. Settings shows the exact event that is sent and lets you reset the install ID.
- **Builds from source send nothing:** only a packaged release holds the key that makes sending possible.
- **The update check sends nothing about you:** it asks GitHub's public releases API with an `Avala` user agent only, once at startup and when you choose Check now. It can be turned off with `{ "checkOnStartup": false }` in `updates.json` in the data folder.

Phone notifications, pull requests and forge triggers talk to the services you configure for them, and only when you set them up.

## Known limitations

- This is a beta prerelease. Being a prerelease build, it is told about later prereleases as well as stable releases.
- Windows and Linux only for now; macOS packages come later.
- Packages are unsigned (see above).
- Avala updates itself only when installed with the Windows installer, the portable zip or the AppImage; from the tar.gz or the AUR it tells you a newer version is out, and your package manager updates it.
- No Flatpak on Flathub yet; the Flatpak can be built from the tar.gz.
- Claude Code is the only supported harness.
- Receiving webhooks from the internet needs a tunnel of your own, such as Tailscale Funnel; Avala listens on loopback only.
