**Your team's agents on one dashboard, jobs that outlast a usage limit, and checks Avala finds by itself.**

The first preview of Avala 0.2, for Windows and Linux. It is a **prerelease**: expect rough edges, and please report them. Installed with the Windows installer, the portable zip or the AppImage, 0.1.0-preview.2 and earlier offer this update in place.

## Highlights

### A fleet server for your team

Run a server of your own, and every Avala on your team sends it what its jobs do. The new **Fleet** page shows spend and tokens over 7 days to 12 months, split by repository, computer and model, down to each job of a repository.

- **Your server, your data.** It receives each job's repository, statuses, model, tokens, cost and verification, and never a path, a title, an instruction, a prompt or a file name. Nothing is sent from a chat without a repository.
- **Ready to deploy.** `deploy/fleet/` holds a Docker Compose file with PostgreSQL, the server and Caddy for HTTPS, and a `fleet` command to register and revoke computers and to back up and restore the database. The image is `ghcr.io/rick-dev-creator/avala-server:0.2.0-preview.1`, for `linux/amd64` and `linux/arm64`.
- **Keys that stay put.** Each computer's key is kept in its system keychain and sent only to your server, over HTTPS.
- **Optional.** Nothing changes until you connect a server in **Settings, Fleet**. The [Fleet server guide](https://github.com/rick-dev-creator/avala/blob/main/docs/guide/fleet-server.md) shows how to install one.

### Elastic Harness Chaining: a job that outlasts a usage limit

When a job nears the limit of its connection's usage window, it no longer just stops.

- **Wind-down.** At 90% of a window by default, the agent is asked to finish its step, leave the work in a valid state, stop its sub-agents and write what is left.
- **Relay.** The next connection takes the baton and continues from a brief built from Avala's own records: the instruction, the plan, the files changed, the checks, the decisions and what remains. Across three or four subscriptions, a job keeps going as each window fills and resets.
- **Checks still run** on the wound-down turn, so the brief carries the checks that failed and what to fix.
- **The Relays pane** draws the baton's route across connections, with every leg of the journey.
- **Your rules.** Settings, Connections, **Usage limits** chooses when to prepare, the hard cap, which connection comes next, and the connections in the relay, in order.

### Verified without writing a single rule

A repository without `.avala/checks.json` no longer ends with "nothing proves the work". Its first job starts a scout that finds the repository's own build, lint and test commands, whatever its stack.

- **In an autonomous repository**, the checks that pass are written into the job's diff, so approving it declares them for every later job.
- **In a supervised one**, the card shows the proposed commands with **Use them** and **Skip**, and nothing runs until you choose.

### Worktrees that don't fill your disk

Avala now frees a job's worktree once the job no longer needs it, and keeps its work.

- **The work stays.** Changes stay in your repository under `refs/avala/shelved/<id>`, and a job that continues rebuilds its worktree at the same path and resumes its conversation.
- **Within limits.** A space budget (20 GB) and a disk floor (10% free) free the worktrees idle the longest, never one of a working job.
- **The Worktrees page**, opened from Resources, shows the space by state, the largest worktrees, what is freed next, space by day and what was recovered.

### See it on a phone, in 3D

- **Seven devices.** The preview's **Device** menu shows a page on an iPhone SE, iPhone 16, iPhone 16 Pro Max, Pixel 9, iPhone Duo (open or closed) or iPad Air.
- **In 3D.** **Show the device in 3D** turns the device into a model you can rotate, zoom and pan, with the page still live on its screen.
- **3D files.** A `.glb`, `.gltf`, `.stl` or `.obj` the agent writes opens in a 3D viewer that ships with Avala, and a written page opens in the preview pane.

### And more

- **Settings** shows one section at a time, with a tab per kind of repository rule, and fits narrow windows.
- **Overview** leaves archived conversations out.

## Before you update

- **Ended jobs' worktrees are freed.** Avala's choices apply to worktrees already waiting, so once 0.2 starts it frees the worktrees of jobs that are archived, discarded, failed, or approved with their work delivered, and later those you leave untouched for 3 days.
  - The work stays reachable under `refs/avala/shelved/<id>`, and a job you continue gets its worktree back.
  - The freed work of a discarded job is deleted after 7 days, and of a failed job after 30. Approved work is never deleted.
  - To keep worktrees longer from the first start, set the `worktrees` section of `resources.json` in Avala's data folder before you update, as the [configuration reference](https://github.com/rick-dev-creator/avala/blob/main/docs/reference/configuration.md) describes. Afterwards, **Settings, Worktrees** chooses when each moment frees them.

## Supported harness

- **Claude Code.** Avala runs the `claude` CLI in its streaming JSON mode, so Claude Code must be installed, with `claude` on the `PATH`, and signed in. Avala finds each login on its own: the default `~/.claude` folder, other `~/.claude-*` folders, the folder in `CLAUDE_CONFIG_DIR`, or an API key or token in the environment, and offers a connection for each.

## Check a package before trusting it

`./Avala --version` prints `Avala 0.2.0-preview.1 (<commit>)`, and `./Avala --smoke` starts the real application headless in a temporary data folder and prints `Avala <version> composed <n> pages and showed its main window.` On Windows, pipe them to `Out-Host` in PowerShell.

## Privacy

- **Usage statistics** are unchanged from 0.1.0-beta.1. Anonymous statistics go to [Aptabase](https://aptabase.com), on by default: an `installed` event once and an `active` event at most once per local day, with nothing about your repositories, jobs, prompts, paths, harnesses, connections, accounts, costs or features. Turn them off on the first-run notice, in Settings, About, or with `DO_NOT_TRACK=1` or `AVALA_TELEMETRY=0`.
- **New: a fleet server**, only once you connect one in Settings, Fleet, receives what each job does, as described above. It is your own server, and Avala sends it nothing else.

## Known limitations

- This is a preview prerelease, told about later prereleases as well as stable releases.
- Windows and Linux only for now; macOS packages come later.
- Packages are unsigned.
- Claude Code is the only supported harness.
- **The fleet server:**
  - registered computers cannot be listed yet;
  - there is no web interface: the Fleet page in Avala is how you read the fleet;
  - only one server may run against a database.
