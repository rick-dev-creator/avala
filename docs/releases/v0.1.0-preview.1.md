**Sub-agents in sight, and nothing of yours lost on the way.**

The first preview of Avala, for Windows and Linux, after thirteen betas. It is a **prerelease**: expect rough edges, and please report them. Installed with the Windows installer, the portable zip or the AppImage, a beta offers this update in place.

## What changed since 0.1.0-beta.13

**Every agent at work, as a live tree.** The Delegation pane and Overview › Delegation draw the job you started at the top and, under it, its harness's own sub-agents, its background commands and the child jobs it delegated, on the same harness or another, each with its harness, connection, state, spend and context. Cards appear, flow, turn amber when they wait, red when they fail or are lost, and go still when done; settled branches fold away. A job stays Running while its agent's background work runs, and the agent may go on by itself when that work reports back.

**A sub-agent asks its orchestrator, not you.** A delegated job's questions go to the job that delegated it, which answers or asks you its own question, as Claude Code does with its sub-agents. A sub-agent's permission requests still come to you, naming the sub-agent. An orchestrator held for you is never woken by a sub-agent's question; the question waits and reaches it with your next message. The `escalation` and `parentWindowSeconds` settings are retired and ignored.

**What you do is reviewed by you.** In a pull request round woken by CI, a message, a steer, a message from your phone, an answer, a permission you allow or a budget you raise makes the round yours: it comes back for your review instead of being pushed. Avala's own notes read as Avala's, not as yours.

**No message of yours is lost.** A message queued for a job that can no longer take it comes back into the composer, with its attachments and why. Queued messages survive closing Avala. A message the agent's session can no longer read resumes the conversation in a new session instead of failing the job.

**Pull requests the agent opens itself are adopted with care.** Avala adopts a pull request only when its head commit was made in the job's worktree and the push is certain, including a push by URL, refuses pull requests from forks, and remembers what the agent reported across a restart.

**Fewer questions for read-only commands.** `git log` filters such as `--since yesterday` and unquoted globs such as `ls src/*.cs` run without asking when every match, read on disk and followed through links, stays inside the worktree.

**Feature documentation stays on its job's account.** The documentation companion runs on the job's own connection; when it reaches its usage limit, the conversation shows the version waiting and it goes on by itself when the window resets. A version that cannot be written says why.

**Remote Control after a rest or a restart.** Turning it on for a job whose agent rested resumes the conversation first, and a job open for your phone when Avala quit is reopened for it when Avala starts.

**Smaller things.** The job header fits beside the inspector at 720 px; the Usage page reads whole at 272 px; a live page that cannot read says so; tooltips show only on cut text; the first arrow key on a menu reaches its first or last item.

Everything else is as described in the [0.1.0-beta.13 notes](https://github.com/rick-dev-creator/avala/releases/tag/v0.1.0-beta.13).

## Supported harness

- **Claude Code.** Avala runs the `claude` CLI in its streaming JSON mode, so Claude Code must be installed, with `claude` on the `PATH`, and signed in. Avala finds each login on its own: the default `~/.claude` folder, other `~/.claude-*` folders, the folder in `CLAUDE_CONFIG_DIR`, or an API key or token in the environment, and offers a connection for each.

Each package is self-contained, and every installer and archive has a `.sha256` checksum next to it. The builds are still unsigned: Windows SmartScreen warns about an unknown publisher, and Linux packages are checked against their `.sha256`.

## Check a package before trusting it

`./Avala --version` prints `Avala 0.1.0-preview.1 (<commit>)`, and `./Avala --smoke` starts the real application headless in a temporary data folder and prints `Avala <version> composed <n> pages and showed its main window.` On Windows, pipe them to `Out-Host` in PowerShell.

## Privacy

Unchanged from 0.1.0-beta.1: anonymous usage statistics to [Aptabase](https://aptabase.com), on by default, an `installed` event once and an `active` event at most once per local day, and nothing about your repositories, jobs, prompts, paths, harnesses, connections, accounts, costs or features. Turn it off on the first-run notice, in Settings, About, or with `DO_NOT_TRACK=1` or `AVALA_TELEMETRY=0`. Attachments and drafts stay on your machine; attachments go only to the harness of the job they were sent with.

## Known limitations

- This is a preview prerelease, told about later prereleases as well as stable releases.
- Windows and Linux only for now; macOS packages come later.
- Packages are unsigned.
- Claude Code is the only supported harness.
- No Flatpak on Flathub yet; the Flatpak can be built from the tar.gz.
- The Archived page has no search yet, and nothing is archived automatically.
- A peek shows text files only; images and pages open in their own preview.
- Continue on your phone needs a harness that offers it: today Claude Code signed in with claude.ai.
- The welcome screen's composer does not take attachments yet; attach them once the job has started.
- Whether Claude Code's own sub-agents compact at their connection's window has not been confirmed yet.
- Feature documentation writes a version for a new plan or an attempt that changes it; code the diff touches outside the plan does not write one yet.
- Without declared checks, what counts as the agent's verification and as an edit is read from its commands, so an unusual tool can be misread.
- A fix CI wakes that a reviewer's requested changes drive is pushed without coming back to you.
- A docs site job approved under `keep` leaves the site on its branch; merge it yourself.
